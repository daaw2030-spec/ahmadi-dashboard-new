# لوحة عقد الأحمدي 2025–2026

داشبورد Streamlit يقارن عامي **2025 و2026** لنفس الأشهر، بأربع صفحات:

1. **الملخص المالي** — الأرقام الرسمية (المعتمد، المنصرف، الرصيد المتبقي) ومقارنة الصرف شهريًا وحسب القسم.
2. **أوامر الشراء ودورة المعاملة** — عدد الطلبات، مدة كل مرحلة، حالة الطلبات.
3. **الطلبات المباشرة والملغاة** — المقارنة الشهرية وحسب القسم.
4. **البنود الاستهلاكية** — نسب الصرف من كميات العقد (الملف بلا تواريخ، فلا يُقسم على السنوات).

## مصدر الأرقام الرسمية

ورقة «الرصيد المتبقي واوامر الشراء» في «الملف المتكامل لعقد الاحمدي.xlsx»:
المبلغ المعتمد من خلية الورقة، والمبلغ المنصرف هو مجموع عمود «المبلغ»
(نفس معادلة الورقة `SUM(D2:D288)`)، والرصيد المتبقي = المعتمد − المنصرف.

لا تُحسب هذه الأرقام من السعر × الكمية. القيمة المحسوبة بهذه الطريقة تظهر فقط في صفحة البنود الاستهلاكية بوصفها «تقديرية».

## قواعد تنظيف البيانات

- لا تُحذف أي معاملة بسبب تاريخ غير صحيح.
- التاريخ خارج الفترة من 2024-01-01 حتى اليوم يُعد غير صالح. المدد السالبة أو المبنية على تاريخ غير صالح تُستبعد من المؤشرات الزمنية فقط.
- التواريخ الهجرية تُحوّل إلى ميلادي (أم القرى). إذا غاب تاريخ الأساس، يُستخدم أقرب تاريخ صالح في المعاملة نفسها.

## التشغيل محليًا

```bash
pip install -r requirements.txt
streamlit run app.py
```

## مصدر البيانات عند النشر

البيانات لا تُرفع إلى هذا المستودع العام. عند النشر يقرأها التطبيق تلقائيًا من مستودع خاص
عبر GitHub API، باستخدام مفتاح للقراءة فقط محفوظ في Streamlit Secrets:

```toml
[data_repo]
token = "github_pat_..."          # مفتاح fine-grained بصلاحية Contents: Read-only على المستودع الخاص فقط
repo = "OWNER/PRIVATE_REPO"
ref = "main"
folder = "dashboard_data"
```

تُحدَّث البيانات تلقائيًا كل ساعة. ترتيب المصادر: مجلد `data/` المحلي، ثم المستودع الخاص، ثم شاشة الرفع اليدوي.

## الملفات محليًا

ضع ملفات البيانات في `data/` بالأسماء: `contract_integrated.xlsx`، `purchase_orders.xlsx`، `direct_cancelled.xlsx`، `consumables.xlsx`.
إذا لم تكن الملفات موجودة، تعرض اللوحة شاشة لرفعها. تبقى الملفات المرفوعة في الجلسة فقط ولا تُحفظ.
